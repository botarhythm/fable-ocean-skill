## 決定

lessons/006 の写像チェックを本輸入自体に適用したうえで、**4点を輸入し、規約1点を採用**する。Ocean F2 のコスト構造（従量変数＝Fableのみ・物量＝枠内下位モデル）は Orchestra の前提と同型であり、1〜4はいずれも効き先が存在する。

- **(1) `agent_usage.py` を upstream v0.4.2 で置換**（`skills/ocean/scripts/`）。集計欠陥の修正を含むため無条件で採用。原文を保ち upstream 突合を容易にするが、**Ocean側パッチ1点のみ追加**: Windowsコンソール（cp932）で `≈` が UnicodeEncodeError になるため、stdout をUTF-8に再構成する shim を冒頭に置いた（コメントで明示・突合時は除外）。3モードとも Windows 実機で動作確認済み。`scope_size.py` は突合の結果同一（変更なし）。
- **(2) セッション境界の経済学を SKILL §9 として採用**。判定表（続行/切替/器なしサブエージェント裁定/配備フェーズの枠内化）・モデル途中切替の禁止・「一次情報は生で渡す」の譲れない線。§7 に「構成指定のガバナンス」（次セッションのモデル構成を指定する計画は承認ゲート同格）も併せて採用。
- **(3) 壁打ちステージを SKILL §8 として採用**。独立スキルにはせず `/ocean` 内の工程とする（adr/0004 の単一エントリ方針を維持。`/ocean 壁打ち` で起動できれば十分）。ブリーフ保存先は対象プロジェクトの `docs/briefs/`。
- **(4) input-tokens-primer.md をハブ `docs/` に原文まま収蔵**（出自ヘッダ付与）。§3 見積り提示と §9 の背景教材。
- **(5) 輸入審査の規約を採用**: 外部のコスト施策は自分のコスト構造へ写像してから採否を決める（チェック2点＝効く変数の存在・譲れない線との衝突）。SKILL 統合メモに明文化。

## 輸入しなかったもの

- **lessons/005 の「P1任意実験」**（従量サブエージェントにツール実行権を持たせて検収3点セットを実施させる構成）— Orchestra 側でも未検証の実験項目であり、条文としては輸入しない。Ocean で必要になったら upstream の実験結果を確認してから検討する。
- **effort運転の廃止**（lessons/006 で Orchestra が見送った施策の逆輸入）— Ocean は effort運転（01 §4・adr/0002）を**維持**する。写像すると: Orchestra は「定型仕事はそもそも型に入らない」トポロジーだが、Ocean は定型実装（Sonnet帯）も型の内側で回すため effort レバーに仕事が当たる。また枠が枯渇して下位モデルまで実質従量に振れる局面（F2の背景そのもの）では金額に直接効く。構造が違えば採否も違う — これ自体が (5) の規約の適用例。
