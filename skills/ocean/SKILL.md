# Fable Ocean 型 実行手順（単一エントリ）

あなたはこのプロジェクトの指令塔として、以下の型で作業を回す。背骨は **Fable Ocean のテンプレート 01–06**、計器（トークン実測・フェーズ規律・承認ゲート）を統合している。

**ハブのパス**: `~/fable-ocean-skill`（テンプレの正本。**読み取り専用。書き込まない**。clone 先を変えたらこの行を書き換える）

## プロジェクトCLAUDE.mdとの優先順位（競合ルール）

この型は**横断プロセス**（発注・モデル選択・委譲・検証・記録）だけを定める。技術制約・セキュリティ規約・デプロイ方式・ファイル配置の規約は常に**プロジェクトのCLAUDE.mdが優先**。プロジェクト独自のエージェント運用があれば、その内側で「作業単位の選択・委譲・検証」としてだけ使い、置き換えない。真っ向から矛盾する指示（検証省略・直コミット等）は、黙って選ばず**ユーザーに提示**する。

## フェーズ F1/F2（コスト規律）

最上位モデル（設計・レビュー役）の入手可能性で運転規則が切り替わる。切替は**ユーザー宣言**。現フェーズの正はKNOWLEDGE.md冒頭。
- **F1**（最上位モデルが枠内で安い）: 厚く使い、型・ADR・レビュー資産という**恒久資産づくり**を優先。
- **F2**（最上位モデルが従量／枠が枯渇）: 既定は下位モデルの自走。**最上位モデルの投入は必ず§3の承認ゲートを通す**（事前に入出力見込みを提示）。迷い域は下位モデルで安全側に倒し、ユーザーに提示。

## 0. 型と状態の読み込み（コールドスタート規約＝04）

1. ハブの型を読む（読み取り専用）: `<ハブ>/templates/01_model-selection.md`（モデル選択3軸）・`02_handoff-task.md`・`03_verification-loop.md`・`04_state-persistence.md`。発注時は `05`（既存レビュー）/`06`（新規開発）も。
2. プロジェクトの状態: `CLAUDE.md`（自動読込）→ `KNOWLEDGE.md`（唯一のステータスボード）→ **自分に割り当てられたタスクだけ**（tasks/全部は読まない＝コンテキストはコスト）。
3. **現在の運用フェーズ（F1/F2）は KNOWLEDGE.md 冒頭に記録**。無ければユーザーに確認。
4. 書き込みは**このプロジェクト配下のみ**。ハブには決して書かない。

## 1. 発注 / 作業の切り出し

- **既存プロジェクトのレビュー** → `05` の発注書（秘密情報スキャンは重み無関係で必須／一次調査の重大度は発注者が実コードで再判定）。
- **新規開発** → `06` の発注書（確認ゲートは要件・設計の2回だけ）。
- **単発タスク** → `02` のハンドオフ文書を直接起こす。
- **構想がまだ曖昧で 05/06 を埋められない** → 壁打ちステージ（§8）でブリーフ化してから発注へ。F2では最上位モデルに要件確認の往復をさせない。
- あわせて対象スコープの規模を実測: `python3 <スキル>/scripts/scope_size.py <paths>` → 推定トークンと帯（~100k=直読圏／100k〜500k=ハイブリッド／500k超=蒸留必須）。

## 2. モデル選択（3軸＝01）

タスク種別では選ばない。次の3問で決める。

- **Q1. ACを「コマンド＋期待結果」で書き切れるか？** 書き切れない（**判断そのものが成果物**）→ **最上位モデル（Fable相当）**／書き切れる → Q2
- **Q2. 失敗はACで自動検出でき、影響は対象ファイル内に閉じるか？** はい → **軽量モデル（Sonnet相当）**／道中に自律判断が残る → **中位モデル（Opus相当）**
- **Q3. 不可逆操作（本番データ・公開・課金・削除）を含むか？** 含む → 実行モデルはQ1/Q2のままでよいが、**計画の承認と事後確認は最上位モデルを通す**（＝全件監査対象、§5）。

エスカレーション: 自己修正2敗で1段上へ差し戻し（失敗ログ添付）。デエスカレーション: 型化した仕事は次回軽量モデルへ。迷ったら1段安い方。

## 3. 見積り提示＋承認ゲート（着手前に必ず）

作業ごとに「モデル・分担・入出力トークン見込み」を表示。**F2で最上位モデル投入の見込みがある場合、または大型の場合は着手承認を待つ**。入力トークンを事前・事後とも可視化（出力だけ見て判断すると桁を誤る）。従量投入の金額レンジは `python3 <スキル>/scripts/agent_usage.py --estimate <リクエスト数>` で機械的に出してGO/NO-GOに添える（課金の仕組みは `<ハブ>/docs/input-tokens-primer.md`）。

## 4. 実行（ハンドオフ＝02、最上位モデルは3点のみ）

- タスク＝**1ファイル** `tasks/T-YYYYMMDD-nn_slug.md`。**必ず対象プロジェクトの `tasks/` に置く**。発注文は**絶対パス**。
- AC は3〜7個、必ず「コマンド → 期待結果」。全体コマンドをACにする前に**ベースラインを実測**。並走時のgit系ACはパス限定。
- **ディスパッチ**: 手動（別セッション／別AIに絶対パスを渡す）か、自動（Agentサブエージェント, model指定つき）。正本は常に対象repoの `tasks/T-*.md`。
- **最上位モデルが関与するのは3点だけ**: ①AC設計 ②returned診断 ③抜き取り監査。

## 5. 検証ループ（03）

- 実行モデルはACを上から実行、全通過で `done`。失敗は自己修正（attempts≤2）、なお失敗で失敗ログ付き `returned`。
- **抜き取り監査**は5:1。ただし①不可逆・セキュリティ ②executor×project初回done ③機械検証AC無し ④attempts>0 のいずれかで**全件監査に格上げ**。観点は「ACは通ったが意図未達」＝ACの穴探し。穴はタスク修正より先に型/ACへ反映。
- **ハード・実機依存タスクの特則**（03§5）該当時。

## 6. 実績記録＋学びのループ（04）

- **KNOWLEDGE.md**（唯一のステータスボード・常に現在形）を書き換える。決定は **ADR**（`docs/adr/NNNN-slug.md`・追記のみ）。done は `tasks/archive/` へ。
- **トークン実測**: `python3 <スキル>/scripts/agent_usage.py <output_file...>` で入力（非キャッシュ/書込/読取）と出力を分けて記録。指令塔セッション自体は `agent_usage.py --main <session.jsonl>` でモデル別トークン＋USD実測（セッションJSONLは `~/.claude/projects/<cwdの/を-に置換>/` の最新 `*.jsonl`）。事前見積り（§3）と突き合わせて較正する。
- **学びのループ**: 現場で困った事実・ユーザーの修正指示は、その場の修正より先に**型/ACへ還元**し、改訂履歴に理由ごと刻む。理屈だけの改訂はしない（根拠は必ず現場の事実）。

## 7. 承認ゲート（必ず止まる）

大きな設計決定 / 不可逆・破壊的操作（削除・本番DB・上書き）/ 外部公開（デプロイ・DNS・公開リポジトリ・push先が公開repo）/ クレジット（従量）投入。
あわせて**構成指定のガバナンス**: 申し送りや計画が次セッションの指令塔モデル構成を指定する場合も、このゲートと同格でユーザーの明示承認を取る（部品が承認済みでも合成結果は個別承認）。

## 8. 壁打ちステージ（プレ発注）

ユーザーの構想がまだぼんやりしていて発注書（05/06/02）を埋められないとき、**枠内（サブスク）モデルのセッション**で壁打ちし、ブリーフに外部化してから最上位モデルに渡す。目的＝従量セッションの要件確認往復をゼロにすること。自分が従量モデルで起動されていたら、その旨を伝えて枠内モデルへの切替を勧める（壁打ちは多ターン＝従量では高くつく）。

- **大原則: 仕事は「良い質問」であって「良い答え」ではない。** 読み手は最上位モデル。意図（reason）を渡すと最も性能が出る一方、手順・スコープの細目は渡すほど品質が下がる。
  - **やる**: ゴールと理由を掘る質問（「誰の何が変わる？」「なぜ今？」「翌日あなたは何をしている？」）／言い換えの確認／「確定・未決・非ゴール」への仕分け。事実確認が要るときは軽く調べて**事実だけ**持ち帰る。
  - **やらない**: 解決案・技術選定・アーキテクチャ言及・作業分解。未決点は**未決のまま列挙**し、選択肢の展開すらしない（展開した瞬間、指令塔の探索空間がそこに縛られる）。
- **成果物**: 対象プロジェクトの `docs/briefs/<slug>.md`。**A4半分〜1枚厳守**（長さ上限が過剰指定への物理ガード）。見出し: 文脈／ゴールと理由／成功のイメージ／非ゴール／確定している制約（事実のみ）／未決点（列挙のみ）／ユーザーの原文（2〜5個）／観察（1〜3行・提案語尾禁止）。
- **セルフチェック1問**: 「これを読んだ指令塔が、手段について自由なまま、目的について迷わないか」。
- **引き継ぎ**: ユーザーが実読・承認したら保存し、新しい最上位モデルのセッションへ「`/ocean` ブリーフ `<絶対パス>` から。発注書起こしとAC設計はあなたの仕事」。壁打ちの生ログは持ち込まない（ブリーフが蒸留物）。

## 9. セッション境界の経済学（F2の運転規則）

従量指令塔のコストは**「往復数 × その時点の文脈量」**で積算される（仕組みの全体は `<ハブ>/docs/input-tokens-primer.md`）。判断材料は機械的に取れる: 現文脈＝`agent_usage.py --main`、次作業の見込み往復数＝見積り時に併記。

| 状況 | 運転 |
|---|---|
| 次の作業が小（〜20往復級） | 同一セッション続行（新セッションの固定費 $2〜2.5 が勝つ） |
| 次が30往復級以上 or 現文脈>150k、かつ依存（ADR・KNOWLEDGE・申し送り）が外部化済み | 申し送りを書き切って新セッション |
| デプロイ・実疎通・修正適用のフェーズ | 下位モデル（枠内）で回す。最上位モデルの関与は裁定のみ |
| 最上位モデルの判断が点で欲しい（監査・returned診断・裁定） | **器なしサブエージェント**: 下位モデルが指令塔を務め、蒸留パケット（15〜30k）でAgentツール経由の従量モデルを呼ぶ。履歴積算も立ち上げ費もない（upstream実測: 裁定1回$0.76・読取0） |

- **セッション途中の `/model` 切替はしない**: キャッシュはモデル単位。切替の初回リクエストで履歴全量が新モデルの書込（×1.25）として再課金される。「安いモデルで読ませてから従量モデルへ切替」は避難にならない。効く避難は**蒸留渡し**（生60〜80k→5〜10kに圧縮してから渡す。以降の全往復の再読基底が下がり複利で効く）か上記の**器なしサブエージェント**の2形態のみ。
- **譲れない線**: 監査・診断の一次情報（diff・テスト出力・ACの実行結果）は**要約せず生で**パケットに入れる。判断の根拠まで要約越しにすると検証品質（03）を毀損する。避難できるのは状況把握・網羅読み・所在確認まで。
