# 01 モデル選択ルール

version: 1.1 (2026-07-02) / 制定: Fable-5

## 0. たたき台の批判と設計方針

当初案は「設計・レビュー = Fable-5、単純実装 = Sonnet 5、中間 = Opus 4.8」だった。この**タスク種別による分類は捨てる**。同じ「実装」でも本番 DB マイグレーションと CSS 修正では必要な知性が違い、同じ「設計」でも前例のコピーで済む設計なら Sonnet で足りる。種別ではなく、次の 3 軸で決める。

1. **曖昧さ** — 仕様の解釈余地・判断の分岐数。ゴールを機械検証可能な受け入れ条件（AC）に書き切れるか。
2. **誤りの検出コスト** — 間違いを AC で自動検出できるか、それとも後から人間が気づくしかないか。
3. **影響半径** — 失敗したときの波及範囲。不可逆か（本番データ・公開・課金・削除）。

## 1. 判定手順（3 問で決める）

- **Q1. このタスクの AC を「コマンド＋期待結果」で書き切れるか？**
  - 書き切れない（判断そのものが成果物）→ **Fable-5**
  - 書き切れる → Q2 へ
- **Q2. 失敗は AC で自動検出でき、影響は対象ファイル内に閉じるか？**
  - はい → **Sonnet 5**
  - 道中に自律判断が残る（複数ファイル横断、既存設計への適合判断、仕様の小さな穴埋め）→ **Opus 4.8**
- **Q3. 不可逆操作（本番データ変更・マイグレーション・公開・課金・削除）を含むか？**
  - 含む → 実行モデルは Q1/Q2 の結果のままでよいが、**計画の承認と事後確認だけは Fable-5 を通す**

## 2. 割り当ての目安

| モデル | 任せるもの | 例 |
|---|---|---|
| **Fable-5** | 判断が成果物になる仕事 | アーキテクチャ・トレードオフ設計 / 規約・テンプレの制定改訂 / レビューの最終判定と優先順位づけ / 2 敗した原因不明バグの診断 / セキュリティ・不可逆操作の計画 |
| **Opus 4.8** | AC はあるが道中に判断が要る仕事 | 複数ファイルにまたがる実装 / リファクタリング / テスト戦略の具体化 / レビューの一次スクリーニング / 仕様の穴を常識で埋めてよい実装 |
| **Sonnet 5** | AC が仕事の全てを規定する仕事 | 単発の機能実装 / 定型実装（CRUD・UI 部品・変換スクリプト）/ 仕様確定済みのテスト実装 / ドキュメント整形 / 機械的な一括変更 |

## 3. エスカレーションとデエスカレーション

- **2 敗ルール（昇格）**: 実行モデルが同一タスクで自己修正 2 回に失敗したら、それ以上粘らせず 1 段上のモデルへ差し戻す。失敗ログ（02 テンプレの実行報告）を必ず添える。3 回目の試行を同じモデルでやらせるのが一番高くつく。
- **型化ルール（降格）**: Fable-5 / Opus が一度解いてパターン化した仕事は、2 回目以降 Sonnet に降ろす。「1 回目は上で解いて手順書にし、N 回目は下で回す」が基本形。
- **迷ったら 1 段安い方**に出す。エスカレーション経路が失敗を回収するので下振れの損は小さい。逆（高いモデルに安い仕事）は回収できない。

## 4. effort レベル（モデルと直交する第 2 のレバー）

| モデル | 推奨 effort | 起動コマンド例 |
|---|---|---|
| Fable-5（設計・レビュー） | xhigh | `claude --model claude-fable-5 --effort xhigh` |
| Opus 4.8（判断の残る実装） | medium（難タスクのみ high） | `claude --model claude-opus-4-8`（必要時 `--effort high`） |
| Sonnet 5（定型実装） | low | `claude --model claude-sonnet-5 --effort low` |

運用の仕組み（詳細は docs/adr/0002。仕様確認 2026-07-02）:
- グローバル設定は `medium` を床にする（7/7 作業終了後に `setup/apply-effort.ps1` で適用）。
- Fable_Ocean のプロジェクト設定は `xhigh`（設定スコープはプロジェクト > ユーザーの優先で自動適用）。
- ハンドオフ文書の `effort:` フィールドが個別タスクの指定値。発注時の起動コマンドに反映する。セッション中の変更は `/effort <level>`。
- 未設定時のモデルデフォルトは high。**下げ忘れは静かにコストになるが、上げ忘れは品質低下として気づける** — だから床は低めに置き、明示的に上げる。

## 5. コスト原則（従量課金後の大前提）

- **Fable-5 の出力は必ず「再利用される文書」に落とす。** 1 回の思考を仕様書・規約・ADR として N 回使う。チャットで消える回答に Fable-5 を使わない。
- コンテキストもコスト。下位モデルのセッションには必要最小限の文書だけ読ませる（04 のコールドスタート規約参照）。
