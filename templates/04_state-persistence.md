# 04 状態永続化の規約

version: 1.0 (2026-07-02) / 制定: Fable-5

前提: Fable-5 は常駐しない。**新規セッションの Opus/Sonnet が、誰にも聞かずにファイルだけで動き出せる**状態を常に保つ。

## 1. ファイル台帳（プロジェクトルートに置くもの）

| ファイル | 役割 | 書く人 | 更新タイミング | 性質 |
|---|---|---|---|---|
| `CLAUDE.md` | ほぼ不変の規約: プロジェクト概要・構造・起動/テストコマンド・コーディング規約・本規約群への参照 | 人間 + Fable-5 | 構造や規約が変わったときのみ | 長寿命・自動読込 |
| `KNOWLEDGE.md` | **唯一のステータスボード**: いま何が真か（進行中の作業、直近の決定、既知の問題） | 全モデル | 状態が変わるたび | 常に現在形。ログではない |
| `docs/adr/NNNN-slug.md` | 決定記録: **なぜ**そう決めたか | Fable-5 | 重要な決定時 | 追記のみ・書き換えない |
| `tasks/T-*.md` | 作業指示と実行報告（02 テンプレ） | Fable-5 が発注 / 実行モデルが報告 | タスクごと | 短寿命。done は `tasks/archive/` へ |

**書き分けの原則**: 「なぜ」= ADR / 「いま何が真か」= KNOWLEDGE.md / 「何をするか」= tasks/ / 「恒常的にどうやるか」= CLAUDE.md。迷ったら KNOWLEDGE.md に書き、あとで昇格させる。

## 2. コールドスタート規約（新規セッションの読み順）

下位モデルの新規セッションは次の順で読み、**それ以外を読まない**（コンテキスト＝コスト）:

1. `CLAUDE.md`（自動で読み込まれる）
2. `KNOWLEDGE.md`（現在の状態を把握）
3. **自分に割り当てられたタスクファイルだけ**（`tasks/` 全部を読まない。ADR はタスクから参照されているものだけ）

発注側（Fable-5）の義務: タスクファイルはこの 3 点だけで実行可能なように書く。足りない文脈はタスク内に引用するか、特定ファイルへのパス参照で示す。

## 3. KNOWLEDGE.md の書式

```markdown
# KNOWLEDGE.md — <プロジェクト名>
Last synced: YYYY-MM-DD

## 現在の状態
- <進行中のこと、直近に完了したこと>

## 有効な決定（詳細は ADR 参照）
- <決定の1行要約> (adr/NNNN)

## 既知の問題・注意点
- <ハマりどころ、触ってはいけない箇所と理由>

## 変更履歴
- YYYY-MM-DD: <1行>
```

運用ルール:
- 1 トピック 1 エントリ。古くなった記述は追記でなく**書き換える**（ステータスボードであってログではない）。
- Claude の私有メモリ（`~/.claude/projects/<slug>/memory/`）を更新したら、**同一ターンで** KNOWLEDGE.md も更新する（ユーザーレベル Skill `project-knowledge-sync` の規約と同一。他の AI は KNOWLEDGE.md しか読めない）。

## 4. ADR の書式（最小構成）

```markdown
# NNNN <決定のタイトル>
- 日付: YYYY-MM-DD / 決定者: fable-5
## 状況
<何が問題だったか。1 段落>
## 決定
<何をすると決めたか。1 段落>
## 理由と却下した代替案
<なぜこれか。何を捨てたか>
## 影響
<この決定で変わること、縛られること>
```

番号は 0001 から連番。決定を覆すときは古い ADR を消さず、新しい ADR で「0003 を置き換える」と書く。
